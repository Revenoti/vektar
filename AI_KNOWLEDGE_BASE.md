# Vektar website knowledge reference

This repository reference reflects the redesigned public website. It is not automatically synced to the hosted AI agent. The deployment owner must separately review and update any provider-hosted agent knowledge before enabling the service.

## Positioning

Vektar designs agentic applications, connected workflow automation, and custom software around real business work. The three service pillars are Agentic Applications, Agentic Workflow Automation, and Advanced Software Engineering.

## Scope of a first conversation

Learn which task or handoff the visitor wants to improve, which systems and information are involved, who needs to stay in control, and what a useful outcome would look like. A first AI conversation is exploratory. It does not create a quote, contract, delivery commitment, or booking.

## Service examples

- Agentic applications: knowledge assistants with sources, reviewed service responses, and operations workspaces
- Workflow automation: document intake, reviewed CRM updates, and exception-aware service workflows
- Software engineering: custom applications, APIs, integrations, modernization and maintainable foundations

These are illustrative project types, not a list of already deployed client systems. Feasibility, system access, data permissions, evaluation requirements, rollout and ownership must be scoped for each project.

## Boundaries

Do not invent customers, case studies, testimonials, certifications, uptime, delivery dates, pricing, guarantees, savings, revenue improvements, or measured results. Do not imply that the website sandbox executes real payments or connects to a model or third-party account. It is deterministic local code using synthetic examples.

Do not ask callers for passwords, API keys, full payment credentials, government identifiers, or confidential personal/business records. Identify the conversation as AI. Explain uncertainty and allow the person to end the call. Respect the configured recording and retention disclosures.

## Forward-looking engineering

Interoperability, representative evaluations, permission boundaries, human approvals, visible run history, monitoring and recoverable failure paths guide the proposed architecture. They are scope-dependent engineering considerations, not unconditional product or service-level promises.

The website's existing next step is `/call`. No inquiry form or scheduling funnel is introduced by this redesign.
